# MAI 内置人设清单

> 这份文档记录系统当前自带的 AI 人设，并提出一个面向「人间百面」的两级分类，用来引导后续人设库扩充的方向。
>
> 内置人设来源：`backend/app/seed.py::BUILTIN_PERSONAS`（共 12 项 = 10 个 discussant + 1 个 scribe + 1 个 facilitator）。
>
> 每个人设都带 `color`（十六进制主题色）和 `icon`（lucide 图标名）。前端 `frontend/src/components/PersonaIcon.tsx` 维护可用图标的白名单，新增图标时必须同步 `backend/app/schemas.py::PERSONA_ICON_NAMES` —— `PersonaDraftEnvelope` 用这个枚举校验 AI 起草输出的 icon 字段。

## 1. 分类原则

人设库不应只服务"开会评审"。MAI 是一个让多视角同时在场的讨论室，可以承载的不止职场场景：江湖里的辩论、日常生活里的取舍、学问里的提问、创作里的批评、趣味里的思想流派对话——都是合理使用方式。

为此用**两级分类**组织：

- **一级**按"人在什么场景下需要多视角"划分（职场 / 江湖 / 日常 / 学问 / 创作 / 趣味 / 元角色）。
- **二级**按这个场景里的细分职能或视角划分（例如职场下的"技术与系统 / 产品与用户 / 安全与合规"）。

> **元角色**单独一级 —— 它们是任何讨论都可能用到的"调度型"人设（反方律师、钢人化支持者、研究侦察员、书记官、上帝副手），不绑定具体场景。

## 2. 一级分类总览

| 一级 | 定位 | 现有 / 候选数 |
|---|---|---|
| **元角色（Meta）** | 跨场景的讨论结构性人设 | 现 5 / 候选 0 |
| **职场（Workplace）** | 技术、产品、商业、合规、内部协作 | 现 7 / 候选 11 |
| **江湖（Civic）** | 公共议题、辩护、经济、历史、政策的视角对撞 | 现 0 / 候选 12 |
| **日常（Daily life）** | 关系、家庭、健康、个人理财、生活选择 | 现 0 / 候选 11 |
| **学问（Learning）** | 教学、提问、领域知识载体 | 现 0 / 候选 4 |
| **创作（Creative）** | 文学、剧本、批评，独立于产品上下文 | 现 0 / 候选 6 |
| **趣味（Playful）** | 性格原型、思想流派代言人、虚构视角 | 现 0 / 候选 6 |

> 当前 12 个内置人设里有 5 个是元角色（含 2 个系统角色 scribe / facilitator），7 个是职场子类——这就是"过于专注职场"的来源。江湖、日常、学问、创作、趣味目前是 0。

## 3. 元角色（Meta） — 跨场景

这一级的人设特点：不绑定行业，靠"讨论中的姿态"提供价值。任何讨论都可以拉一两个进来，用来打开 / 收回 / 记录场子。

### 3.1 讨论调度型（现有 3）

| key | 名称 | 提供的姿态 | 温度 |
|---|---|---|---|
| `devils_advocate` | 反方律师 | 系统性提反例、隐藏假设、失败路径，必须有证据 | 0.65 |
| `steelmanner` | 钢人化支持者 | 把弱方案先表达成最强版本再评审 | 0.55 |
| `research_scout` | 研究侦察员 | 提备选路径、未知变量、实验设计、外部线索 | 0.75 |

### 3.2 系统角色（现有 2，由引擎调度）

| key | 名称 | kind | 触发节奏 | 用途 |
|---|---|---|---|---|
| `scribe` | 书记官 | `scribe` | 每 5 条可见消息 | 记录共识 / 分歧 / 问题 / 决议 / 死路 |
| `facilitator` | 上帝副手 | `facilitator` | 每 5 条 + 阶段切换 | 对用户隐藏地评估健康度，给节奏建议 |

> ⚠️ 系统角色不要轻易加同 kind 的并行角色——多个 scribe 会让 `ScribeState` 的合并逻辑复杂化。

### 3.3 候选扩充

| 候选 key | 名称 | 提供的姿态 |
|---|---|---|
| `mediator` | 调解者 | 找共同利益、降低对抗温度 |
| `decision_forcer` | 决策推手 | 强行收敛到可执行结论 |
| `risk_register` | 风险登记员 | 把零散风险结构化为可跟踪条目 |

## 5. 江湖（Civic）

## 6. 日常（Daily life）

朋友、家人、医生、理财顾问——日常生活里最容易缺多视角的就是这一级。这一级的人设要避免"扮演专业医师"的硬建议，定位是"提供视角让用户自己拍板"。

### 6.1 亲友建议（候选 3）

| 候选 key | 名称 | 视角 |
|---|---|---|
| `pragmatic_friend` | 务实朋友 | 直接、不绕、关心可执行 |
| `supportive_friend` | 共情朋友 | 先承认情绪、再讨论选择 |
| `tough_love_friend` | 硬话朋友 | 不留情面但不带敌意 |

### 6.2 关系与家庭（候选 2）

| 候选 key | 名称 | 视角 |
|---|---|---|
| `couple_dialogue` | 伴侣对话顾问 | 表达需求、回避指责、建立修复路径 |
| `family_mediator` | 家庭调解者 | 代际差异、长期关系、避免赢输 |

### 6.3 健康与运动（候选 2，谨慎）

| 候选 key | 名称 | 视角 |
|---|---|---|

## 7. 学问（Learning）

教学场景里最缺多视角。一个老师会被学生的问题暴露盲区，但单 AI 没法提供这种张力——MAI 可以让"导师 + 提问者 + 领域专家"同台。

| 候选 key | 名称 | 视角 |
|---|---|---|
| `socratic_tutor` | 苏格拉底导师 | 用提问把学习者推到下一层 |
| `novice_proxy` | 初学者代理 | 模拟"听不懂"的信号，倒逼讲解 |
| `examiner` | 主考官 | 设计能暴露未掌握处的问题 |
| `domain_expert_template` | 领域专家（参数化） | 由用户填入学科：法律 / 医学 / 历史 / 经济... |

> `domain_expert_template` 是个**参数化模板**：用户复制它后在 system prompt 里填入"你是一位{学科}的资深从业者..."。比堆十个固定学科专家更灵活。

## 8. 创作（Creative）

定位：**为文学作品本身服务**，不是为产品文案。需要的是不同流派 / 不同立场的创作视角对撞。

| 候选 key | 名称 | 视角 |
|---|---|---|
| `novelist` | 小说家 | 人物动机、情节合理性、节奏 |
| `screenwriter` | 编剧 | 戏剧冲突、场景张力、画面语言 |
| `poet` | 诗人 | 意象、声韵、留白 |
| `literary_critic` | 文学评论家 | 流派背景、互文、伦理层 |
| `genre_specialist_template` | 类型小说专家（参数化） | 武侠 / 推理 / 科幻 / 言情... |
| `world_builder` | 世界观构建者 | 内部一致性、规则系统、文化合理性 |

## 9. 趣味（Playful）

把性格原型和思想流派做成"代言人"。**不做具体真实人物的角色扮演**——容易擦边名誉权和事实失真问题。做的是"原型"和"流派"。

### 9.1 性格原型（候选 3）

| 候选 key | 名称 | 提供的姿态 |
|---|---|---|
| `mbti_thinker_template` | MBTI 类型代言（参数化） | 用户填入 16 型中的一种 |
| `enneagram_template` | 九型人格代言（参数化） | 用户填入 1-9 中的一种 |
| `archetype_jester` | 弄臣（小丑原型） | 用反讽和荒诞戳穿严肃的盲点 |

### 9.2 思想流派代言（候选 3）

| 候选 key | 名称 | 提供的姿态 |
|---|---|---|
| `stoic_voice` | 斯多葛派 | 区分"可控 / 不可控"，淡化情绪 |
| `taoist_voice` | 道家 | 无为、顺势、避免过度干预 |
| `confucian_voice` | 儒家 | 关系、礼、长期教化 |

> 思想流派本身是公共领域，不构成名誉风险。但 system prompt 要明确"你是该流派思想的现代代言人"，不要伪造原典引文。

## 10. 同类产品参考（moxt.ai）

[moxt.ai/zh-CN/ai-teammates](https://moxt.ai/zh-CN/ai-teammates) 把 AI 同事按职能划成 8 个大类（产品研发 / 市场增长 / 销售 / 营收 / 运营 / 法务 / 人事 / 财务 / 行政），共 24 个能独立完成 workflow 的"AI 员工"。

- 它的形态是**单 AI 端到端 workflow**，例如"邮件分拣"是一个完整流程。MAI 是**多 AI 同场讨论**，"邮件分拣"这种单人任务并不适合直接搬。
- 但它对**职场子类**的细分很有参考价值，第 4 节的商业经营 / 设计 / 写作子类就是借鉴它的拆法。
- 它没有覆盖**江湖 / 日常 / 学问 / 创作 / 趣味**这四级——因为它的产品定位就是职场工具。MAI 没必要被这个定位限制住。

## 11. 实施注意事项

新增内置人设按下面几条走：

1. **在 `backend/app/seed.py::BUILTIN_PERSONAS` 追加条目**。`key` 一旦发布就不可改（用 UUIDv5 派生 id）；想替换内容只能换 key 或写一次性数据迁移（参考 `migrate_seed_story_mode.py`）。
2. **必须配 `color` + `icon`**。`color` 用十六进制（如 `#22c55e`），从现有调色板里挑；`icon` 必须是 `schemas.PERSONA_ICON_NAMES` / `PersonaIcon.tsx` 白名单里的 lucide 名。新图标先扩枚举再用，否则前端显示 fallback。
3. **温度梯度**遵循当前现有的：
   - 收敛 / 审计型：0.30–0.40
   - 平衡 / 综合型：0.45–0.55
   - 发散 / 探索型：0.65–0.80
4. **system_prompt 要写出能在讨论里产生交锋的姿态**，不要只是"你是 X，请回答用户问题"。参考现有的"你是反方律师。你要强制寻找反例、隐藏假设和失败路径，但必须给出证据或可验证判断。"
5. **标签**第一项必须是 `builtin`，第二项是一级分类的英文 slug（`workplace` / `civic` / `daily` / `learning` / `creative` / `playful` / `meta`），后面再放细分标签。
6. **参数化模板**（`*_template` 后缀）是个新机制：复制后让用户填一个学科 / 流派 / 类型变量。需要在 PersonaTemplate 上新增一个 `parameter_slots: list[VariableDeclaration]` 字段。这是结构性改动，要单独评估。
7. **避开真实人物角色扮演**。原型、流派、虚构身份可以，"扮演鲁迅 / 巴菲特"不行——这条直接写进新增人设的 review 标准。
8. **日常 / 健康类**人设的 system prompt 必须包含"在涉及健康 / 法律 / 财务的关键决策时建议咨询专业人士"的兜底。

## 12. 下一步

- 这份文档是清单 + 路线图，**不是实施计划**。
- 推荐扩充顺序（按"覆盖空白 + 实现成本"排序）：
  1. 元角色补全（mediator / decision_forcer / risk_register）—— 现有引擎能直接吃，没有结构改动。
  2. 职场.商业经营族（market / sales / finance / legal / hr）—— 一次性把 MAI 从"技术评审"扩到"商业决策"。
  3. 江湖族（哲学思辨 + 法律辩护两个子类先行）—— 立竿见影的"多视角对撞"卖点。
  4. 日常族（亲友建议 + 关系家庭先行，健康 / 育儿后置因为风险约束）。
  5. 学问族 + 参数化模板机制（这一组要先做 `parameter_slots` 字段才能落）。
  6. 创作族 + 趣味族 —— 营销和差异化价值，不阻塞主路径。
