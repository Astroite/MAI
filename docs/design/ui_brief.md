1. 整体视觉
- 清新、简洁、冷白背景。
- 主色使用 mint teal / clear-water blue。
- coral 只用于少量警示、冻结、异常状态。
- 避免复杂后台感，不要做成传统 SaaS 管理后台。
- 不要做营销页风格，不要大面积渐变，不要夸张游戏 UI。

2. 布局
- 使用三栏工作台布局
- 桌面端优先。
- 页面整体要像一个干净的创作工作台，而不是普通聊天首页。

3. 组件风格
- 圆角控制在 8px 以下。
- 使用 1px 分割线。
- 使用非常轻的阴影。
- 使用状态 chip 表示：进行中、已封幕、冻结中、未开始。
- 使用轻量线性图标，优先复用 lucide-react。
- 卡片 hover 可以有非常轻微的背景变化或边框变化。
- 不引入大型 UI 框架。

4. 技术约束
- 保持现有 React Query / API / i18n 结构。
- 不删除现有功能。
- 不破坏现有路由、状态管理、API 调用和 i18n。
- 所有新增或调整的用户可见文案必须走 i18n。
- 不要为了视觉效果生成会覆盖、删除或修改已有对话历史的 CRUD 逻辑。
- 如果需要 mock 数据，只能用于视觉占位，并且要清楚隔离，不能污染真实数据层。
- 优先改样式、布局、组件组合和状态展示，不要重构核心业务逻辑。





视觉细节：

1. 页面背景
- 使用冷白背景。
- 可以有非常轻微的 clear-water blue tint。
- 不要使用纯灰后台背景。

2. 卡片
- 白底。
- 1px 浅蓝灰边框。
- 6px 左右圆角。
- 极轻阴影。
- hover 时轻微提升或边框变 mint teal。

3. 按钮
- 主按钮：mint teal 实底，白色文字。
- 次按钮：白底，mint teal 边框和文字。
- 按钮圆角不超过 8px。
- 图标和文字间距清晰。

4. 状态 chip
- 小尺寸胶囊。
- 带圆点状态更好。
- 文案短。
- 色彩低饱和。

5. 字体层级
- Hero title 最大。
- Section title 清晰但不要过重。
- Card title 中等粗细。
- 描述文字使用蓝灰色。
- 避免过多黑色重字。

6. 间距
- 三栏之间要有清楚间隔。
- 中间主区内容不要挤。
- 右侧面板卡片之间保持一致 spacing。
- 世界卡片图片比例统一。

7. 插画 / 封面图
- 如果没有真实资产，使用渐变占位图或现有图片资源。
- 保持低饱和、清透感。
- 不要让封面图抢走 UI 主体。
